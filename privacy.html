Hermes Agent

Privacy Policy

Hermes Agent is a single-user personal AI assistant operated by Kevin Varon on a private server. This policy explains exactly what Google user data it touches, how that data is used and stored, and who it is shared with.

Who this applies to

Hermes Agent is personal, single-user software. It runs on a private server controlled by Kevin Varon, and the only Google account it ever connects to is his own.

There is no public service, no hosted product, no sign up page, and no user accounts. No one other than the operator can authorize the application or use it. If you have arrived here from a Google consent screen, that consent screen belongs to this single personal installation.

Data the app accesses

Hermes Agent requests access to Google APIs on behalf of the operator's own Google account. Specifically:

  • Gmail. Reading messages and threads, drafting messages, sending messages, and replying to messages, in the operator's own mailbox.
  • Google Calendar. Reading and creating calendar events, only if that scope is separately authorized.
  • Google Drive. Reading and writing files, only if that scope is separately authorized.

No data belonging to any other person's Google account is accessed, because no other person can connect an account to this application.

How the data is used

Google user data is used only to carry out tasks the operator asks for directly, in that moment. Typical examples: summarizing what arrived in the inbox, drafting a reply to a specific thread, sending a message the operator approved, or looking up a detail inside an email so it can be acted on.

Google user data is explicitly not used for any of the following:

  • Training, fine-tuning or improving any machine learning or AI model.
  • Building user profiles, behavioral profiles or audience segments.
  • Advertising, marketing or retargeting of any kind.
  • Analytics, measurement or usage statistics, whether first party or third party.
  • Resale, licensing or any other transfer to another party.

Google Limited Use

Limited Use compliance statement

Hermes Agent's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements.

In practice this means: data obtained from Google APIs is used only to provide or improve the user-facing features the operator explicitly invoked; it is not transferred to others except as necessary to provide those features, to comply with applicable law, or as part of a merger or acquisition (neither of which applies to a personal single-user installation); it is not used for advertising; and no humans read the data except the operator himself, acting on his own mailbox.

Storage and retention

OAuth tokens

The OAuth access token and refresh token issued by Google are stored locally on the operator's private server, in the application's own configuration directory on that machine. They are not transmitted anywhere else and are not stored in any cloud service, hosted database or third-party platform. They are retained until access is revoked or the credentials are deleted from the server, at which point they are destroyed.

Message content

Email content, calendar entries and file content are fetched from Google's APIs, held in memory for the duration of the task, and then discarded. Hermes Agent does not build or maintain an email database, a mail archive, a search index of messages, or a long-term copy of Google user data.

The one exception is ordinary, operator-initiated output: if the operator asks the assistant to write a summary or save a note to a file on his own server, that file is his own document on his own machine, and he controls and deletes it like any other file.

Sharing and disclosure

Google user data is shared with no one. There are no third-party recipients, no data processors, no advertisers, no data brokers, no analytics vendors, and no sale or licensing of data under any circumstances.

The only network destination for Google user data is Google's own APIs, which is where the data came from and where replies and actions are sent back. Any data that would leave the operator's server would only ever be the content of a message he himself instructed the assistant to send from his own mailbox.

Security

All communication with Google APIs happens over HTTPS. The private server is under the operator's sole administrative control, credentials are stored outside of any version-controlled or published code, and access to the machine is restricted to the operator. Because the system has exactly one user and no public interface, there is no account surface for anyone else to attack or impersonate.

Revoking access

Access can be revoked at any time, with immediate effect, from the Google Account permissions page:

  • https://myaccount.google.com/permissions

Revoking there invalidates the stored tokens and the application loses all access to Google user data. A deletion request can also be sent to kevinvaron6@gmail.com, and the stored tokens will be deleted from the server.

Changes to this policy

If the application's data handling changes, this page is updated and the date at the top of the page changes with it. The current version is always published at https://k3vin135.github.io/privacy.html.
